## 1. Why this feature

The stock Evennia webclient is a single text pane in a GoldenLayout frame. PolishedWorld's alpha measures onboarding (roadmap decision (G)), and a new player reads the world faster with a location panel, a clock and their own gauges beside the text than with `status`, `look` and `inventory` typed in turn. The art side is ready to be used: the palette is locked, the style guide fixes the Legend vocabulary for the UI, and the body silhouette and its seven zone masks are published under `web/static/polishedworld/`.

What this feature must not do is make the webclient the game. The text stream stays complete for every session (WC1), so a telnet player and a screen-reader player play the same game; panels are a second view of state the server already sends as text, and the one place where the client hides text (WC4) hides only what a visible panel already shows.

## 2. Decisions locked 2026-11-06 (WC1–WC16)

**WC1 — The text stream stays canonical; every panel datum is also reachable in text.** Roadmap [RESOLVED] 2026-09-09 governs: OOB data goes *alongside* text, never instead of it. Where a panel shows something no player command prints today, this feature adds the command (W5.3 adds a player `time`; Evennia's `@time`, open to players (`commands/default/system.py:731–734`), prints server uptime and the game time as a real-calendar timestamp, `system.py:745–756` — not the project's 13 months, season or weather). *(Rev 10)* Rev 1–9 missed that a typed `time` already reached the extended_room contrib's `CmdExtendedRoomGameTime` (`contrib/grid/extended_room/extended_room.py:944–977`, installed with `ExtendedRoomCmdSet`), which printed the season and the period of day in a sentence through the project's Room overrides; only the date and the weather were printed by no player command. W5.3's `time` replaces the contrib's and prints all four; `@time` is untouched (§3 *command names*). *What follows:* no task may remove a line from what a session receives as text; WC4 only splits one message in two.

**WC2 — Own fixed layout; GoldenLayout and every CDN dependency go (D1 = C).** Evennia's `webclient/base.html` loads jQuery 3.2.1, Bootstrap 4.0.0-beta, mustache, popper, GoldenLayout from `golden-layout.com/files/latest` (unpinned, a website rather than a CDN) and favico.js from `cdn.rawgit.com` (§3). The style guide and mockup v3 describe a fixed three-column layout, the accessibility rules need landmarks and a live region in a DOM we control, and a public site must not run an unpinned third-party script. Kept from Evennia, served from Evennia's own static files: `evennia.js`, `webclient_gui.js`, `default_in.js`, `default_out.js`, `history.js` — the input and output plugins fall back to `#inputfield` / `#messagewindow` without GoldenLayout (`default_in.js:16, 52`; `default_out.js:9–12`). jQuery is vendored, version-pinned and hashed (W3.1). *Rejected:* A, keep GoldenLayout from the CDN; B, vendor GoldenLayout — both keep a layout library the design does not use, with its mobile and screen-reader costs.

**WC3 — `webclient/base.html` is replaced, not extended.** The CDN lines sit partly outside the template's blocks (`base.html:19, 83–88, 125, 133–134`), so `{% extends %}` with `{{ block.super }}` cannot remove them. The project's `web/templates/webclient/base.html` is a full replacement; `webclient.html` is extended through its `client` block. The cost — a copy that does not follow Evennia upgrades — is paid by a test that renders the page and fails on any `src`/`href` to a host other than the game's own (W3.1), and by Evennia Ref recording which upstream file the copy was taken from.

**WC4 — Room lists travel as their own text message, type `room_contents` (D2 = C).** Today a look is one message, `type: "look"` (`extended_room.py:632`; auto-look after a move at `objects.py:3236`). The project sends a room look as two messages in order: the description (`type: "look"`) and the exits, characters and things (`type: "room_contents"`). A telnet session receives the same text in the same order as now. The webclient shows `room_contents` in the text area unless the room panel is visible **and** the player has not turned on *room lists in text* (a client toggle, default off on desktop, forced on below the layout breakpoint). One function, `room_look(char, room)`, sends both, and both callers — the look command and `Character.at_post_move` — use it (W5.4). *(Rev 11: three callers, not two — `DefaultCharacter.at_post_puppet` (`objects.py:3281`) also sent the room look, at every puppet, and `Character.at_post_puppet` now uses `room_look` too. The command uses it only with no argument: `look <target>` and `look here` stay one message (W5.4 lock 3A).)* *Rejected:* A, the server omits lists for panel sessions (needs the [RESOLVED] entry rewritten and every list-writer to know a flag); B, accept the duplicate.

**WC5 — OOB is a full snapshot per domain (D3 = B).** Four command names: `survival` (locked by roadmap [RESOLVED] 2026-09-09), `char`, `world`, `room`; `map_update` stays reserved for the map. Each is sent whole — never a delta — when a value in it changes or crosses a threshold, at `at_post_puppet`, and when the client asks. A lost or reordered message is corrected by the next one, and a reconnect needs one request *(Rev 5: it needs none — a reconnect is a new session and a new puppet, so `at_post_puppet` pushes; see WC6)*. Payload shapes are fixed in W4.1 (its *Shipped* line) and documented in Evennia Ref at W8.2.

**WC6 — The client asks with one inputfunc, `pw_state`.** `server/conf/inputfuncs.py` (loaded by `INPUT_FUNC_MODULES`, `settings_default.py:492`) gains `pw_state(session, *args, **kwargs)`, which sends all four snapshots to that session. The `pw_` prefix is required: a later module in that list overrides an earlier function of the same name (`settings_default.py:489–491`). ~~The webclient calls it on login and on page reload, because a browser reload re-attaches to a puppet that is already puppeted, and `at_post_puppet` does not run again.~~ *(Rev 5, falsified by W4.1's browser protocol, step 4:)* a page reload is a new session, and `Account.puppet_object` calls `at_post_puppet` on every path that ends in a puppet (`accounts/accounts.py:554`), so the reload already gets all four snapshots. What skips the hook is `evennia reload`: `ServerSession.at_sync` restores the puppet without it (`server/serversession.py:127`), so an open page gets nothing new until it asks. `pw_state` is the client's pull for that case and for any time it wants its state again; whether the client calls it on connect is W4.3's STOPP 0. *(Rev 7:)* it does not (W4.3 lock 1A): `logged_in` is sent before the auto-puppet (§3 *login order*), so a request on `onLoggedIn` would only repeat the four snapshots. The reload in Rev 5's correction is also a fresh login, not a resumed one (§3 *auto-login*); the hook runs either way.

**WC7 — No per-session client flag.** The handoff assumed the webclient would tell the server it shows panels. With WC4 the server never needs to know: OOB goes to every session, the webclient routes it, and telnet drops it unless the client negotiated GMCP or MSDP (`telnet_oob.py` `data_out`), in which case a GMCP client receives the same snapshots — harmless and free. `client_options` refuses unknown keys (`inputfuncs.py:167`, error text to the player) and `webclient_options` is stored per account (`:539`), so neither would have been the right home anyway.

**WC8 — One emitter module, a census of its call sites.** `world/client_state.py` holds the four pure snapshot builders and `push(obj, *domains)`. Emission happens at named sites only (§3, W4.2), and a test counts them with the AST (lesson 200's method) so a new write to a gauge without a push fails a test instead of shipping a stale panel. The room snapshot is built per viewer, because display names depend on the looker (`get_display_name(looker)`; statues of logged-out characters, WC14).

**WC9 — The clock is computed in the browser.** The `world` snapshot carries absolute game seconds (`world.gametime_utils.get_absolute_gametime()`), `TIME_FACTOR` (4) and the server's wall-clock milliseconds at the moment of sending; JS advances the clock locally and renders date, time of day and season with the project's month names. Evennia's game time only runs while the server runs, so the snapshot is re-sent on puppet, on `pw_state`, on each weather change and on each survival tick (every 600 real seconds, `SURVIVAL_TICK_INTERVAL` in `server/conf/at_server_startstop.py`; *(Rev 6)* Rev 1–5 said every 30 real minutes, which is the weather script's interval, not the tick's) — the largest possible drift is one server downtime, corrected at the next connect.

**WC10 — Pixel art scales only by whole factors, rendered `image-rendering: pixelated`.** From the style guide §5. The silhouette shows at ×2 or ×4; icons at ×1 or ×2.

**WC11 — The outline moves to a lighter palette colour (D4 = B).** `#0E1512` against Panel is 1.14:1 and against Panel light 1.43:1, so neither surface makes the outline a graphical object at the 3:1 the style guide requires. ChatGPT redraws the outer outline in a palette colour that is ≥ 3:1 against Panel and occurs nowhere else in the figure — candidates `muted` `#9D9B8C` (5.78:1) and `stone_light` `#B0ADA0` (7.20:1); `stone` `#777C79` is already used inside the figure and cannot be told apart from it by the pipeline. `split-body` then excludes both the new outline colour and Background (inner dark details such as the eyes may stay `#0E1512`) from every mask. The final colour is Adam's and ChatGPT's choice within that constraint (W2.3, §14).

**WC12 — The character panel shows only what the server holds (D5 = B).** The server has one `health` gauge (CON × 2, character creation CC9) and a `fatigue` survival gauge on 0–100; it has no hit locations, no wound levels, no Combat Actions and no Hero Points — all Stage 5, and combat is outside the alpha.
