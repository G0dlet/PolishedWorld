Hard-won working rules for building PolishedWorld with Claude: how source is read, how claims are checked, how patches are verified and delivered. Every rule here cost at least one failed step to learn.

## How to read this register

- **Numbers are permanent.** A lesson is never renumbered or reused, because handoffs, decompositions and commit discussions cite them by number.
- **One line per lesson:** the rule in bold, then one sentence on why, then where it was first written.
- **Refinements get a new number.** When a later lesson sharpens an earlier one, the earlier line keeps its text and gains *refined by N*; read the highest number in the chain as current.
- **Origin** names the epic and task of the session that wrote the lesson, and the date of the handoff that carried it.
- **Adding lessons.** Handoffs keep carrying the lessons a session learns; they are appended here in batches, with the next free numbers, in the docs commit that closes an epic. Until then a handoff says which numbers it adds beyond this register.

## Lessons

1. **Mutate at least once per component, and prove an equivalent mutant equivalent.** A suite never seen killing a mutant is unproven. *(Origin: Adam to fill; first listed 2026-10-15; refined by 480)*
2. **"Nothing changed" needs an independent receipt that the code ran.** An unchanged state is also what a step that never executed leaves behind. *(Origin: Adam to fill; first listed 2026-10-15; refined by 256, 318)*
3. **A write past a single-writer names the invariant it bypasses, and cleans up first.** Single-writer domains (P-2) hold only while every exception is explicit. *(Origin: Adam to fill; first listed 2026-10-15)*
4. **Assert the collection is non-empty before every "all satisfy X".** An empty collection passes every universal check. *(Origin: Adam to fill; first listed 2026-10-15; refined by 266)*
5. **Prose has no tests — your own new prose included; run its claims against the source before commit.** Nothing fails when a document is wrong. *(Origin: Adam to fill; first listed 2026-10-15)*
6. **A diagnostic that can succeed without having searched is worse than none.** It turns a gap into false confidence. *(Origin: Adam to fill; first listed 2026-10-15)*
7. **Read the diff before commit, and assert exactly one match before every replacement.** Zero or several matches mean the edit landed nowhere or somewhere else. *(Origin: Adam to fill; first listed 2026-10-15)*
8. **Changelogs are append-only and descending; read the top before numbering.** Anchoring on a remembered revision produced a duplicate Rev. *(Origin: Adam to fill; first listed 2026-10-15; refined by 417)*
9. **Confirm the branch with `git status`/`git rev-parse` before running the suite.** A green suite on the wrong branch is a receipt for nothing. *(Origin: Adam to fill; first listed 2026-10-15)*
10. **A mutation harness restores from copies and lets the assert stop the loop.** A harness that carries on after a failed assert leaves mutants on disk. *(Origin: Adam to fill; first listed 2026-10-15)*
11. **Expected values in a protocol are read and computed from the source.** Values written from memory make a correct run look wrong, or the reverse. *(Origin: Adam to fill; first listed 2026-10-15; refined by 264, 325)*
12. **"Expected failures" are verified by name on every run, against the right configuration.** A count alone cannot tell the known failures from a new one. *(Origin: Adam to fill; first listed 2026-10-15)*
13. **Absence after a timer needs a time margin or a receipt.** Checked too early, "it didn't happen" and "it hasn't happened yet" look the same. *(Origin: Adam to fill; first listed 2026-10-15; refined by 319, 460)*
14. **A receipt is tested negatively before it is promised.** A check never seen to fail cannot be trusted to. *(Origin: Adam to fill; first listed 2026-10-15)*
15. **Do not claim intent from form: the form is a finding, the intent is a question.** Only Adam can say what a shape in the code was meant to do. *(Origin: Adam to fill; first listed 2026-10-15)*
16. **"No line looks like X" is the §11d trap — spy on the call, or compare state before and after.** Matching on message text misses output phrased differently. *(Origin: Adam to fill; first listed 2026-10-15)*
17. **The prose loop sees new files only when it is run again after them.** A loop run before a file existed says nothing about that file. *(Origin: Adam to fill; first listed 2026-10-15)*
18. **A decision that arises during implementation is still a decision: flag it, log it, let Adam veto it.** Silent in-flight choices become undocumented design. *(Origin: Adam to fill; first listed 2026-10-15)*
19. **Receipts and anchors are quoted from the source, never from memory.** Hashes and line numbers drift between sessions. *(Origin: Adam to fill; first listed 2026-10-15)*
20. **The mutator is atomic: validate every replacement before anything is written.** A half-applied mutation leaves a file that matches neither state. *(Origin: Adam to fill; first listed 2026-10-15)*
21. **A spy on a method misses aliases bound in the class body; when the question is "was anything written", compare state.** The alias still calls the original function. *(Origin: Adam to fill; first listed 2026-10-15)*
22. **The guide header and the commit message are prose too.** They are read as claims and go stale like any other text. *(Origin: Adam to fill; first listed 2026-10-15)*
23. **A task is done when Adam has reported suite and in-game; do not start the next one before that, even on "continue" — ask what is meant.** Only Adam's environment proves the task works where it will run. *(Origin: Adam to fill; first listed 2026-10-15)*
24. **The tool-output display mangles `<name>` into `<n>`; generate anchors from the files, never from the display.** The files are correct and the rendering is not; verify with `grep -c` or `od -c`. *(Origin: Adam to fill; first listed 2026-10-15)*
25. **One expected value cannot tell a correct read from a hard-coded one: use two values, different from each other and from the default, with the premise asserted.** A test that a constant would pass proves nothing about the read. *(Origin: Adam to fill; first listed 2026-10-15; refined by 428)*
26. **"Any order" is a claim — try every permutation before it goes into a guide.** Order dependence hides in the combinations nobody ran. *(Origin: Epic A TA2.3, 2026-10-15)*
27. **A finding in a screenshot (a stale branch, a squeezed column) is verified against the source or GitHub before it becomes a claim either way.** Prompts and renderings lag the real state. *(Origin: Epic A TA2.3, 2026-10-15)*
28. **A harness's reading of results needs its own receipt: no `Ran` line, stop.** Django reports on stderr, so a stdout-only harness reports nothing for every mutant. *(Origin: Epic A TA3, 2026-10-17)*
29. **A guide or patch must fail on second application — try it, don't assume it.** A block that re-applies cleanly can silently double an edit. *(Origin: Epic A TA3, 2026-10-17)*
30. **Configuration is read from the source: confirm with `git stash list` and `settings.py` before judging "expected failures".** A clean-tree prompt meant `#10` was not active. *(Origin: Epic A TA3, 2026-10-17)*
31. **Line numbers move with every docs commit: read anchors from current `main`, never from a handoff (this one included).** A handoff is a snapshot of a tree that no longer exists. *(Origin: Epic A TA3, 2026-10-17; refined by 304, 425, 464, 476)*
32. **A check that crashes has not failed — it has not searched.** The negative run must give FAIL lines, not a traceback; guard against empty sets (`all([])` is True). *(Origin: Epic A TA3 close-out, 2026-10-17)*
33. **Filter on file names, not on line content.** A census filter `grep -v <decomp>` dropped two history lines that only mentioned the decomposition. *(Origin: Epic A TA3 close-out, 2026-10-17; refined by 473)*
34. **The sandbox `bash_tool` runs `/bin/sh`, where `**` does not expand; run the catalogue loop in `bash -c 'shopt -s globstar …'` — the count is the receipt.** The loop said "checked 5" until it ran under bash. *(Origin: Epic A TA3 close-out, 2026-10-17; refined by 154)*
35. **A falsified claim can lack the keyword: search for the mechanism, not just the attribute name.** The `craft_cooldown` search missed `cooldowns.add("craft:<name>")` and "rate limiting on … craft". *(Origin: Epic A TA3 close-out, 2026-10-17)*
36. **`git am` gives a new commit SHA: cite the tree as the receipt, and the SHA only once it is on origin.** The committer date changes the SHA; the tree proves the content. *(Origin: Epic A TA3 close-out, 2026-10-17)*
37. **Tag occurrences are not items: count at the level the claim is about, and say which.** `[DATA]` gave 110 occurrences but 44 items. *(Origin: alpha milestone decision, 2026-10-17)*
38. **A `startswith` filter and an `==` filter give different counts: pick one, print which, and use it for every figure in the same text.** Mixed filters made figures in one document disagree. *(Origin: alpha milestone decision, 2026-10-17)*
39. **A tag "blocked on X + Y" is blocked on both; run the census script before the text is written, not after.** First-token split gave 27 and substring 33, and the text was wrong until the script was rerun. *(Origin: alpha milestone decision, 2026-10-17)*
40. **`c=$(grep -c … || echo 0)` yields "0\n0" when grep misses; write `c=${c:-0}` without `||`.** `grep -c` prints 0 and exits 1, so the comparison crashes and looks like a FAIL (lesson 32 again). *(Origin: alpha milestone decision, 2026-10-17)*
41. **When a decision-log entry goes from [OPEN] to [RESOLVED], keep the old name in parentheses in its heading.** Other entries and older Rev citations grep for that heading. *(Origin: alpha milestone decision, 2026-10-17)*
42. **Recount the census with a saved script against the patched tree as the last step, not the first.** Three figures in the presentation were wrong; the patch was right only because the script was rerun. *(Origin: alpha milestone decision, 2026-10-17)*
43. **Classify the checks before running them: a check that passes in both trees is an invariant, not evidence.** Five invariants filed as NEW passed unpatched and tested nothing about the patch. *(Origin: death-consequence policy, 2026-10-17)*
44. **Blockquote continuation lines carry `> `; a multi-line `old_str` into a changelog or quote without the prefix has never searched.** The §12 check failed in both trees for that reason. *(Origin: death-consequence policy, 2026-10-17)*
45. **An `&&`/`||` chain reports the `||` branch when any earlier link fails; receipts are sequential steps that print their own exit code.** "TREE DIFFERS" was never a comparison. *(Origin: death-consequence policy, 2026-10-17)*
46. **`TREASURY_DBREF` on `main` is commented out, so `sed` on `^TREASURY_DBREF` matches nothing.** The stash is then empty and the receipt runs against the wrong premise without saying so. *(Origin: death-consequence policy, 2026-10-17; refined by 292)*

48. **A [RESOLVED] entry that makes X persist creates code debt wherever X is reset today: file the BACKLOG entry in the same patch, BLOCKED on the epic that makes X real.** That epic then reads it before, not after. *(Origin: death-consequence policy, 2026-10-17)*
